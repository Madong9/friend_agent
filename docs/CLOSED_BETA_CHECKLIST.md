# 5～30 人封闭内测清单

本阶段只发布体验版，不提交正式上线审核。

首次使用 3～4 个真实微信号进行功能验收时，先执行
[3～4 人体验版测试方案](SMALL_BETA_TEST_PLAN.md)，通过后再按本清单扩展人数。

## 开始前

- [ ] 已拥有正确的小程序 AppID，体验版成员已加入后台
- [ ] `API_MODE=sdk`，Publishable Key 仅作为客户端发布密钥，CloudBase 匿名登入及 Gateway/`callContainer()` 已真机通过；历史 `apiMode` / `apiBaseUrl` 不会覆盖发布 transport
- [ ] 已在 CloudBase SQL 编辑器执行 `cloudbase_schema.sql`，并验证容器重启后 Data API 数据仍在
- [ ] `WECHAT_APP_SECRET`、`LLM_API_KEY`、随机 `JWT_SECRET` 只存在云环境变量
- [ ] `DEV_AUTH_MODE=false`
- [ ] 阿里百炼 `qwen3.7-flash` 可用；若保留 Mock fallback，已向内测者明确结果可能由 Mock 生成
- [ ] `SHOW_MOCK_USERS=true` 时，所有虚拟候选都显示“测试用户”
- [ ] 隐私说明、拉黑、举报入口在真机上可访问
- [ ] AI 性格分析必须先勾选同意，且“删除性格分析”在真机可用
- [ ] Mock 参与的 Mutual Match 明确显示测试匹配且不能聊天
- [ ] 已完成至少一轮备份与恢复演练

## 发布体验版

1. 在小程序后台添加 5～30 名体验成员。
2. 开发者工具上传代码并设为体验版。
3. 体验成员扫码前告知：测试用户是虚拟数据，不代表真实同学；不得在简介或聊天中公开手机号、微信号、住址等敏感信息。
4. 分批开放：先 2 人冒烟，再 5～10 人，稳定后最多扩到 30 人。

## 每位体验者的任务

- [ ] 完成画像并二次打开确认保存
- [ ] 用自然语言分别找一次学习、运动或兴趣搭子
- [ ] 用一个当前没人选择的陌生活动创建需求，再由另一位用户选择同活动并检查通知
- [ ] 至少对三张卡片完成 LIKE/PASS/NOT_RELEVANT
- [ ] 验证一次 Block，记录该候选是否再次出现
- [ ] 找另一位真实体验者完成双向 LIKE
- [ ] 测试一次举报入口（内容写“内测功能验证”，避免误判真实事件）
- [ ] 第二天再次打开并完成一次推荐

## 最小指标

| 指标 | 计算方式 | 先观察什么 |
|---|---|---|
| 画像完成率 | 保存完整画像人数 / 新用户数 | 表单是否太长、字段是否难懂 |
| 找搭子成功率 | 返回至少一名可用候选的请求 / 有效请求 | Intent、硬过滤是否过严 |
| 卡片反馈率 | LIKE+PASS+NOT_RELEVANT / 展示卡片数 | 推荐是否值得决策 |
| Mutual Match 率 | 真实 Match 数 / 真实 LIKE 用户数 | 冷启动与活跃密度 |
| 次日回来率 | 次日再次打开人数 / 首日新用户数 | 是否有持续价值 |

同时记录请求失败率、P95 响应时间、Mock fallback 次数、举报数和 Block 数。样本很小时只看方向，不把百分比当统计结论。

服务端聚合快照可执行：

```bash
python scripts/beta_metrics.py
```

输出只包含聚合数量和比例，不包含用户 ID、消息、Prompt、性格原文或 Secret。需求履约率以 `partner_requests` 的 `FULFILLED / 全部需求` 为口径；次日回来率以首次记录交互后的下一个自然日再次产生交互为口径。

## 每日运营检查

- [ ] 健康检查、错误日志和 CloudBase Data API 请求正常
- [ ] API/微信/LLM Secret 没有出现在日志
- [ ] 检查举报，必要时手动停用账号或下线体验版
- [ ] 导出数据库备份并验证文件可读
- [ ] 汇总 UX 问题、失败请求和用户原话，不收集无关隐私
- [ ] 出现隐私泄露、骚扰或越权时立即停止内测并保留审计记录

## 结束标准

形成一页复盘：人数、五项指标、前三个失败场景、前三个高频需求、是否继续保留 Mock 候选，以及下一轮只做哪三项改进。未经这一轮验证，不优先投入 WebSocket、复杂审核后台、向量数据库或多 Agent。
